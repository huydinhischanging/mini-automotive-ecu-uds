\chapter{CONCLUSION AND FUTURE WORK}
\label{ch:conclusion}

\section{Conclusion}

This report presented the design of a miniature automotive ECU network and the completion of its first four milestones. A Sensor ECU on an STM32G431 publishes an end-to-end protected speed signal at 500\,kbit/s with the designed timing, and a Control ECU on the Cortex-M4 of an STM32MP157 receives it under FreeRTOS, checks it, supervises it for faults and drives a safe-state output. The protocol and service layers are portable and backed by 56 passing unit tests, including a full-length ISO-TP transfer. Both ECUs were verified on hardware in internal loopback with zero communication errors over tens of thousands of frames, and the Control ECU answers UDS requests, turns monitor results into DTCs with ISO~14229 status bits and lets a tester read and clear them, as shown by a 14-step on-target test. On the physical two-node bus, injected faults propagated from the Sensor ECU through CAN to the Control ECU, which reacted within its timing requirements and stored the expected DTCs.

The most instructive part of the work was the bring-up of the Control ECU on a heterogeneous SoC, where two defects outside the application code, a missing interrupt handler in generated code and a clock multiplexer blocked by the clock state left by Linux, were located by reading the running firmware's memory and registers from Linux and were fixed in a way that survives code regeneration and a cold boot.

\section{Future Work}

\begin{enumerate}
  \item \textbf{Bus measurement.} Capture the bus with a logic analyser to measure the bit time and sample point of both nodes.
  \item \textbf{DTC persistence.} Keep DTCs across power cycles (the M4 has no flash; storage through Linux or an external EEPROM) and add aging of confirmed DTCs.
  \item \textbf{Core reset.} Coordinate a true Cortex-M4 reset with Linux (remoteproc) instead of the firmware restart.
  \item \textbf{Tester.} A Python UDS client on Linux using SocketCAN, either through a USB-CAN adapter or the second FDCAN controller of the STM32MP157.
  \item \textbf{Quality.} A fix for the HAL tick rate, moving the FDCAN clock configuration into the Linux device tree, and timing measurements (task execution times, interrupt latency).
  \item \textbf{Documentation.} A demonstration video of the complete fault-to-DTC-to-tester flow.
\end{enumerate}
